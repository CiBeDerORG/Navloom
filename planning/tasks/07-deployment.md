# M3 · 安装任务、Compose 执行与自动导航（T-071～T-088）

> P0 · 18 项。**Compose up 退出码 0 = 部署成功**；v1 不做健康检查。任务结果、应用实例和导航卡片必须避免重复。

- [ ] **T-071｜P0｜持久化安装任务与状态机**
  - 对应需求：DEP-01、DEP-03、NFR-02。
  - 前置：T-006、T-056。
  - 交付：任务 ID、模板/版本、Agent、实例引用、状态、时间戳、结果/退出码、导航草稿、日志索引。
  - 验收：任务跨 Server 重启保留；状态只能按允许的路径转换；通信中断不直接变成“部署失败”。

- [ ] **T-072｜P0｜安装前 Agent/Docker/参数/冲突预检**
  - 对应需求：CAT-03、DEP-07。
  - 前置：T-046、T-063、T-064；决策 Q-12。
  - 交付：校验 Agent 在线、Docker/Compose 可用、模板平台适配、参数完整、Compose project/目录与明显端口冲突。
  - 验收：不满足条件时阻止或明确提示；端口预检不被宣传为完全无冲突保证。

- [ ] **T-073｜P0｜创建安装任务 API 与幂等请求键**
  - 对应需求：DEP-01、DEP-05。
  - 前置：T-015、T-071、T-072。
  - 交付：仅管理员可提交；保存参数引用、导航草稿和唯一幂等键；同请求重复提交返回同任务。
  - 验收：重复点击提交不生成两条执行任务；非法模板/Agent 被拒绝；不会将敏感值放入响应。

- [ ] **T-074｜P0｜Server 持久化任务调度与 Agent 下发**
  - 对应需求：DEP-01、DEP-03。
  - 前置：T-044、T-071、T-073。
  - 交付：任务领取、等待/执行状态转换、目标 Agent 路由、派发确认、超时处理。
  - 验收：仅目标 Agent 收到任务；Server 重启后仍可恢复待处理记录；派发成功不等于部署成功。

- [ ] **T-075｜P0｜离线 Agent 任务提交策略**
  - 对应需求：DEP-03。
  - 前置：T-040、T-072、T-074；决策 Q-12。
  - 交付：明确离线时拒绝提交或允许排队的行为与 UI 提示，避免无反馈任务。
  - 验收：离线 Agent 的提交结果与已确认策略一致；不会把等待连接的任务误标为执行中。

- [ ] **T-076｜P0｜Agent 受控 Docker Compose v2 执行器**
  - 对应需求：DEP-01、DEP-02、AGENT-05。
  - 前置：T-045、T-046、T-063。
  - 交付：受限 Compose up 执行、工作目录限制、进程退出码采集、超时/取消处理、并发控制。
  - 验收：正常退出码 0 被原样上报；非零退出码原样上报；不接受任意 Shell 命令或未验证路径。

- [ ] **T-077｜P0｜部署工作目录、Compose project 与环境文件管理**
  - 对应需求：DEP-01、DEP-07。
  - 前置：T-063、T-076。
  - 交付：每个实例稳定的部署目录、project 命名规则、Compose/env 文件生成和权限控制。
  - 验收：同一 Agent 的不同实例不会覆盖彼此；重复任务不会创建冲突目录；敏感文件权限受限。

- [ ] **T-078｜P0｜Agent 安装日志实时回传与 Server 存储**
  - 对应需求：DEP-04。
  - 前置：T-039、T-071、T-076。
  - 交付：带 task_id 和序号的日志消息、增量存储、敏感值脱敏、流量/大小限制。
  - 验收：管理界面可按序读取日志；断线后已落库日志不丢失；敏感安装参数不直接输出。

- [ ] **T-079｜P0｜Compose 退出码与部署结果判定**
  - 对应需求：DEP-02、DEP-04。
  - 前置：T-076、T-078。
  - 交付：退出码 0 → 部署成功；非零 → 部署失败；通信丢失 → 状态待确认。
  - 验收：不会因 HTTP 不可达或 healthcheck 不通过把退出码 0 改判失败；UI 文案只称“部署成功”。

- [ ] **T-080｜P0｜Agent 本地任务执行记录与重放防护**
  - 对应需求：DEP-05、NFR-02。
  - 前置：T-071、T-076。
  - 交付：Agent 记录 task_id、执行状态和已完成结果；重复命令直接回报已有结果或安全拒绝。
  - 验收：同 task_id 重放不重复执行 Compose；Agent 进程重启后仍能识别已执行任务。

- [ ] **T-081｜P0｜Server/Agent 重连后的任务状态对账**
  - 对应需求：DEP-03、DEP-05。
  - 前置：T-038、T-071、T-080。
  - 交付：状态待确认任务查询、Agent 结果补报、重复结果去重与恢复策略。
  - 验收：执行中断网再重连不会盲目二次部署；可恢复最终退出码；无法确认时继续标记待确认。

- [ ] **T-082｜P0｜安装失败结果、残留资源提示与重试入口**
  - 对应需求：DEP-04。
  - 前置：T-079、T-081。
  - 交付：失败原因、日志、退出码、可能残留资源的提示；明确区分“重试任务”与“重新安装”。
  - 验收：失败不创建导航卡片；不假定 Compose 失败后已自动回滚；重试不会绕过幂等保护。

- [ ] **T-083｜P0｜部署成功后创建应用实例记录**
  - 对应需求：INV-04、DEP-01、DEP-06。
  - 前置：T-056、T-071、T-079。
  - 交付：成功任务关联唯一 AppInstance，记录 Agent、模板版本、Compose project、部署路径和时间。
  - 验收：同任务重复成功回报不创建多个实例；外部容器不自动成为受管实例。

- [ ] **T-084｜P0｜导航自动创建的事务与幂等约束**
  - 对应需求：DEP-05、DEP-06。
  - 前置：T-019、T-071、T-083。
  - 交付：任务成功后持久化“导航待创建/已创建”状态，按任务唯一键只创建一次卡片。
  - 验收：Server 在实例保存后崩溃，重启仍能补建卡片；重复回报不会生成第二张卡片。

- [ ] **T-085｜P0｜使用安装前草稿自动创建导航卡片**
  - 对应需求：CAT-04、DEP-06。
  - 前置：T-069、T-083、T-084；决策 Q-07。
  - 交付：将安装前填写的名称、图标、分组、URL 复制为卡片，并关联应用实例。
  - 验收：成功部署生成一张可编辑卡片；失败部署不生成；不会覆盖用户自定义 URL。

- [ ] **T-086｜P0｜安装任务列表、详情与实时日志 UI**
  - 对应需求：DEP-03、DEP-04。
  - 前置：T-073、T-078、T-079、T-082。
  - 交付：任务状态、目标 Agent、开始/结束时间、退出码、日志查看、失败提示与待确认状态。
  - 验收：管理员可追踪一条任务从提交到结束；断网/刷新后仍能查看已存日志；状态文案准确。

- [ ] **T-087｜P0｜同 Agent 的部署并发与资源冲突保护**
  - 对应需求：DEP-05、DEP-07。
  - 前置：T-072、T-074、T-077。
  - 交付：按 Agent/Compose project/部署目录实施互斥或排队；资源冲突返回可理解错误。
  - 验收：两个并发请求不能同时写同一部署目录；不同 project 可按安全策略并发；重复任务不重复部署。

- [ ] **T-088｜P0｜安装成功/失败/断线/重复提交全链路测试**
  - 对应需求：DEP-01～DEP-07、NFR-05。
  - 前置：T-071～T-087。
  - 交付：真实 Compose 简单与多容器模板测试、退出码 0/非零、重复请求、Agent 重连、Server 重启及自动导航测试。
  - 验收：成功只生成一个实例和一张卡片；失败零卡片；状态待确认能恢复；不依赖健康检查通过。

## 里程碑验收

管理员能选择 Agent 和模板、编辑安装参数与导航草稿、查看 Compose 日志；成功自动生成一张导航卡片，失败保留可追溯任务，重复请求不重复部署。
