# 产品决策记录与待确认事项

> **已确认** = 用户已明确决定；**建议** = 为落地提出、尚待确认；**待确认** = 开发前需要选择。任务应遵守本表。

## A. 已确认

| ID | 决策 | 影响 |
| --- | --- | --- |
| D-01 | 产品面向个人自托管、单管理员 | 不做多用户/RBAC |
| D-02 | Server 固定安装在云端 | 可使用 Node.js / Fastify |
| D-03 | Web 用 Vue 3 + TS，Server 用 Fastify + TS，Agent 用 Go | 前后端共享类型，Agent 独立 |
| D-04 | 首页是默认入口，展示已编排的导航卡片 | 管理功能不占据首页 |
| D-05 | 管理后台要求管理员账号密码 | 管理 API 服务端校验 |
| D-06 | 管理后台两个主要业务模块：导航页管理、应用实例管理 | 其他功能作为子视图或设置 |
| D-07 | 首页首次访问需弱口令；后台可修改 | 只读导航门禁 |
| D-08 | 浏览器记住首页验证，凭据存在且有效则免输入 | 采用长期 HttpOnly Cookie 凭据，不存明文弱口令 |
| D-09 | 导航卡片独立存在，不强绑定容器/应用 | 删除卡片不操作 Docker |
| D-10 | Agent 主动发现已有容器到容器池 | 不自动创建导航卡片 |
| D-11 | 新建导航卡片可从容器池选择对象 | 预填信息可编辑 |
| D-12 | 导航 URL 支持手动设置，不假设浏览器可访问 EasyTier 地址 | 避免自动推断错误地址 |
| D-13 | 一个云端 Server 管理多个设备 Agent；EasyTier 已有 | WSS 与身份认证仍必需 |
| D-14 | 所有 Agent 拥有所在设备最高 Docker 管理能力 | 不做 Agent 角色权限 |
| D-15 | 安装通过 Agent 执行 Docker Compose | Server 只调度，不直连 Docker |
| D-16 | Compose up 退出码 0 即部署成功 | 不以健康检查/HTTP 可达性判定 |
| D-17 | v1 暂不做健康检查 | 状态文字必须准确 |
| D-18 | 安装弹窗自动预填可编辑导航信息，成功后创建一张卡片 | 任务与卡片创建需幂等 |
| D-19 | Navloom 是全新独立项目，不继续修改 FlatNas | 规划以新仓库为准 |
| D-20 | Server 可通过内网/EasyTier 主动访问 NAS | 改为 Server 主动建立 Agent WSS，Agent 仅私网监听 |
| D-21 | 无已登录管理员页面时 Agent 与 Server 完全零通信 | 关闭 WSS、停止 Ping/轮询/重连/上报，不注销、不修改最后状态 |
| D-22 | 至少一个已登录管理员页面在线才启动唯一全局 Agent 连接/心跳系统 | 多页面共享、最后一个关闭即停；普通首页访客不计入 |
| D-23 | Agent 心跳只使用 WSS Ping/Pong | 全局可配置间隔、自动/手动模式、手动按钮；取消 JSON heartbeat |
| D-24 | 任意已登录管理员页面可修改 Agent 全局连接探测配置 | 配置持久化、跨页面同步；未关闭的后台标签页仍算在线 |
| D-25 | M2 从 T-036～T-059 全面按反向按需 WSS 重新实现和验收 | T-034/T-035 保留成果；旧主动连接 CI 不能视作新架构验收 |

## B. 建议，尚未单独确认

- R-01：首页弱口令修改后撤销所有旧通行凭据；支持后台手动撤销。
- R-02：导航一级分组、拖拽排序、基础搜索、响应式布局、主题。
- R-03：管理员首次初始化通过部署环境或 CLI，不开放公共注册。
- R-04：Agent 首次接入采用一次性配对令牌。
- R-05：容器基本操作启动/停止/重启为 P0，日志查看也纳入 P0。
- R-06：应用模板初期随仓库版本化管理。
- R-07：失败任务不自动创建导航卡片，状态未知需对账。
- R-08：不提供任意 Shell/终端执行入口。
- R-09：Agent 离线时显示最后快照及过期标记。
- R-10：任务与导航创建必须持久化、幂等。

## D. 决策变更规则

1. 用户确认 Q 项后，将其移入“已确认”，并注明日期。
2. 更新 PRD 对应条目、TRACEABILITY 和受影响的任务。
3. 若与已完成任务冲突，新增变更任务，避免无记录地重写历史。
