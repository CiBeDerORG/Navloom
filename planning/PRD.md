# Navloom 产品需求文档（PRD v0.2）

> 状态：需求基线草案。**已确认**来自产品讨论；**建议**是待确认的落地方案。  
> 产品：个人自托管、导航优先、多 Agent 应用管理与远程 Docker Compose 部署。  
> 代码仓库：https://github.com/CiBeDerORG/Navloom  
> 更新日期：2026-10-11。相关执行任务见 [tasks/README.md](./tasks/README.md)。

## 1. 产品目标与定位

Navloom 面向拥有 NAS、FNOS、Linux 设备及云服务器的个人自托管用户。用户打开网站首先进入**导航首页**，访问自己编排的 Web 应用和普通链接；需要修改导航或管理设备时，才进入受管理员登录保护的**管理后台**。

核心闭环：**打开导航 → 管理后台 → 发现现有容器或选择应用模板 → 远程部署 → 自动创建可编辑导航入口**。

产品原则：
1. 导航是独立的一等对象，不依附 Docker；导航卡片可完全不关联容器。
2. Server 固定部署在云端，多个 Go Agent 部署在设备端，利用现有 EasyTier 网络通信。
3. Agent 主动发现已有容器，进入容器池；不会未经用户选择就把所有容器加到导航首页。
4. 应用部署由 Agent 执行 Docker Compose v2；Compose 命令**正常返回退出码 0**就定义为“部署成功”，v1 不做健康检查。
5. v1 单管理员、个人自托管，不做多用户和角色权限；管理员可管理全部 Agent。
6. 安装弹窗预填可编辑的导航信息；安装成功后自动创建**一张**导航卡片，失败不创建，避免重复创建。

## 2. 页面与用户入口（PROD-01、PROD-02）

导航首页为网站默认路由。管理后台为独立路由，业务一级导航**只有两个模块**：
- **导航页管理**：导航卡片、分组、排序、从容器池选择关联对象。
- **应用实例管理**：Agent、已部署实例、容器池、应用目录、安装任务；内部可以用标签页或子页面组织。

管理员登录和系统设置是辅助入口，不构成第三个主要业务模块。

### 典型使用场景

- 日常：打开首页 → 首次输入弱口令或自动识别已记住浏览器 → 浏览分组/搜索 → 点击卡片。
- 管理导航：点击管理 → 输入管理员账号密码 → 新建或编排卡片 → 返回首页立即看到变更。
- 关联旧服务：Agent 发现既有容器 → 容器池显示 → 创建卡片时选 Agent/容器 → 填写实际 URL → 保存。
- 安装新应用：应用实例管理 → 选模板和 Agent → 填参数及导航信息 → 下发任务 → Compose 退出码 0 → 记录实例并新增卡片。
- Agent 离线：后台显示离线及最后同步时间；导航卡片不被删除；未确认的任务保持待确认状态。

## 3. 首页访问与管理员认证

### AUTH-01 首页弱口令【已确认】

首次使用一个浏览器访问导航首页时，显示弱口令验证页。口令可在管理后台修改。弱口令**仅授予导航只读访问**，不得调用管理、Agent、容器和部署 API。

### AUTH-02 记住浏览器【已确认，已采纳安全实现建议】

首次正确输入弱口令后，Server 签发随机、可撤销的长期访问凭据，保存为浏览器持久化、HttpOnly、Secure、SameSite Cookie；**不将明文弱口令存入 localStorage**。只要本地有效凭据仍存在且未被撤销，就免再次输入。关闭浏览器不应使凭据失效；清除 Cookie、换设备或凭据被撤销时需要重新验证。长期凭据可续期；浏览器自身清理策略不受 Navloom 保证。

### AUTH-03 管理员认证【已确认】

管理入口要求管理员用户名和密码。独立于首页弱口令。管理员登录成功后使用独立会话；支持退出、会话失效后重新登录、修改管理员密码。服务端必须对每个管理 API 校验管理员会话，而不是仅在前端隐藏页面。

### AUTH-04 首次初始化【建议】

首次部署时应有安全的管理员初始化机制。建议通过部署配置/CLI 初始化，**不开放任何人可抢注管理员的公开注册接口**。初始化完成后关闭引导入口。

### AUTH-05 凭据撤销与限流【建议】

管理员修改首页弱口令时使旧的首页通行凭据失效；后台提供撤销所有已记住浏览器的入口。首页弱口令与管理员密码以适合密码存储的哈希保存；验证接口实施限流，管理会话配置 CSRF 防护。

## 4. 导航首页与导航页管理

### NAV-01 首页展示【已确认】

首页只展示用户编排并保存的导航卡片；不直接显示容器池或 Agent 列表。导航内容可以指向 Web 应用、内网服务或普通外部网站。显示卡片名称、图标、分组和可选描述；点击打开配置的 URL。

### NAV-02 卡片独立性【已确认】

导航卡片可独立创建，不必绑定任何应用或容器。字段建议：稳定 ID、名称（必填）、URL（必填）、图标、描述、分组、排序、可选关联对象、打开方式（待确认）。删除卡片**绝不**触发 Docker 删除或应用卸载。

### NAV-03 分组与排序【建议纳入 v1】

新建、重命名、删除、排序一级分组；组内卡片拖拽排序、跨组移动。删除分组需明确卡片如何迁移或处理，不可无提示丢失卡片。是否支持嵌套分组尚待确认；默认建议 v1 只做一级。

### NAV-04 搜索、响应式与主题【建议纳入 v1】

按名称搜索、桌面/移动端适配、基础明暗主题；卡片大小、复杂布局、壁纸等高级定制不作为 P0。卡片打开方式待确认，默认建议新标签页并可配置。

### NAV-05 从容器池关联【已确认】

创建/编辑卡片时可从已发现容器池选择 Agent 和容器，也可选择 Navloom 部署的应用实例。可预填名称、图标和候选 URL，但用户可修改；不能假定 EasyTier 内网地址一定可被浏览器访问。关联失效时保留卡片，允许提示失联。容器重建不能仅靠临时容器 ID 维持关联。

### NAV-06 导航管理【已确认】

管理后台支持卡片增删改、分组管理、布局编排、关联对象选择。编辑结果保存后首页同步展示。一个实例能否关联多张卡片尚待确认；建议允许。

## 5. 应用实例管理、Agent 与容器池

### AGENT-01 Agent 注册【已确认；接入流程待确认】

一个 Server 支持多个 Agent；每个 Agent 有唯一 ID、显示名称和独立身份凭据。建议一次性配对/注册令牌完成首次接入，管理员可撤销凭据。接入流程待最终确认。

### AGENT-02 通信【已确认】

Agent 主动连接云端 Server，采用 WSS 和版本化 JSON 协议；现有 EasyTier 负责网络互通但不替代认证。支持断线重连和任务结果回报；Server 不直接远程挂载 Docker Socket。

### AGENT-03 在线状态【已确认】

Agent 心跳、最近通信时间、在线/离线状态、版本、操作系统/架构及 Docker 可用性可见。离线时明确展示最后一次状态时间，不将缓存信息伪装为实时数据。

### AGENT-04 Agent 管理【已确认】

管理员可查看所有 Agent、修改显示名称、查看连接状态和撤销 Agent 接入。Agent 在设备上具备完整 Docker 管理权限，不做 Agent 分级权限。

### AGENT-05 操作安全【必须实现】

Server 仅向已认证 Agent 下发已定义的受支持命令；Agent 对任务参数做二次校验。v1 不开放任意 Shell/终端执行入口，避免最高权限 Agent 成为通用远程执行通道。

### INV-01 主动容器发现【已确认】

Agent 发现 Docker 上**所有**容器（包括非 Navloom 安装、运行中及已停止的容器），同步名称、ID、镜像、状态、端口、Compose labels、Agent ID、发现时间和最后同步时间。使用定期全量同步加 Docker 事件增量同步的方式属于建议实现。

### INV-02 容器池展示【已确认；展示模式待确认】

应用实例管理下提供容器池，可按 Agent 查看、搜索、按状态筛选、查看容器详情；外部发现对象与 Navloom 部署实例区分。**按容器列表还是按 Compose 项目分组仍待确认**，不得作为已定稿。

### INV-03 容器基本操作【已讨论，建议 P0】

支持启动、停止、重启容器和状态刷新；日志查看建议纳入 v1。执行操作需要管理员认证、Agent 回报结果和明确的失败提示。删除容器、卸载应用及数据清理不在 P0。

### INV-04 应用实例【已确认概念】

“应用实例”是 Navloom 管理的一次应用部署，可对应多个 Compose 容器；与单个容器不同。记录实例 ID、模板/版本、Agent、Compose project、安装时间、任务和关联卡片。外部发现的容器/Compose 项目先归入容器池，不自动冒充 Navloom 安装的实例。

### INV-05 状态与关联【建议】

Agent 离线后保留最后一次容器清单并显示“数据可能过期”。删除卡片不影响容器；容器消失不自动删除卡片；容器重建后尽可能通过 Agent ID、Compose project/service 等稳定标识恢复关联。

## 6. 应用目录、模板与远程安装

### CAT-01 应用目录【已确认】

管理员在应用实例管理中浏览可安装应用，查看名称、图标、描述、分类和适用平台，选择目标 Agent。v1 模板来自项目内置目录还是外部 deploy 仓库尚待确认；建议首版内置版本化模板，后续支持远端仓库。

### CAT-02 模板格式【已确定技术方向】

YAML 描述模板元数据、Compose 配置引用、安装参数和导航默认值；JSON Schema 描述安装参数的类型、必填项、默认值及校验。模板需有稳定 ID 和版本。

### CAT-03 参数与安全【必须实现】

动态安装表单根据 Schema 生成；敏感参数不可明文记录到任务日志；校验目标 Agent 在线、Docker 可用、必填字段、Compose project/部署目录冲突，尽可能提示端口冲突。模板必须为可信来源，不允许任意用户通过安装表单注入 Shell 命令。

### CAT-04 默认导航配置【已确认】

安装弹窗自动预填导航卡片的名称、图标、分组、URL 等信息；管理员在提交前可编辑。是否允许勾选“不创建导航卡片”待确认；默认行为是成功后创建一张卡片。

### DEP-01 远程安装流程【已确认】

选择模板 → 选择 Agent → 填写参数和导航信息 → 提交 → Server 持久化任务 → Agent 执行 Compose v2 → 回传日志与结果 → 成功时记录实例和创建导航卡片。

### DEP-02 部署成功定义【已确认】

**Docker Compose up 命令返回退出码 0 即为“部署成功”。** 不进行健康检查、不要求 HTTP 可达、不因容器健康状态改变部署任务结论。UI 必须区分“部署成功”“容器运行状态”“导航 URL 可达性”。

### DEP-03 任务状态【建议】

至少包括：等待中、执行中、部署成功、部署失败、状态待确认。Server 和 Agent 重启或断连时，不能将“通信中断”直接判定为部署失败。

### DEP-04 日志与失败处理【建议】

实时或近实时展示日志；任务保存创建/开始/结束时间、目标 Agent、模板版本、退出码、错误原因。失败不创建导航卡片；可能残留的容器、网络和目录需提示，不自动假设已经清理。

### DEP-05 幂等与恢复【必须实现】

任务 ID 唯一；重复请求不得重复安装或重复创建卡片；Server 重启不丢失任务；Agent 重连后上报未确认任务结果；状态未知时先核实，不盲目重跑。

### DEP-06 自动导航【已确认】

部署成功后以安装时保存的导航草稿创建**一张**卡片，卡片与实例可选关联；若创建失败需记录可恢复的待处理状态，避免“部署成功但导航无声丢失”。

### DEP-07 资源冲突【建议】

同 Agent 上同 Compose project、安装目录及明显端口冲突应预检和提示；预检不能替代部署结果。重复安装需由业务幂等规则约束。

## 7. 非功能需求

- **NFR-01 安全**：HTTPS/WSS；管理员会话、首页访问凭据、Agent 凭据隔离；密码安全哈希；限流、CSRF、防泄露、最小暴露面；不开放任意命令。
- **NFR-02 可靠性**：SQLite 持久化、迁移、备份；任务状态恢复；Agent 重连；容器快照过期标记；导航创建幂等。
- **NFR-03 易用性**：导航首页优先、移动端可用、操作反馈明确、可编辑自动填充值、错误信息可读。
- **NFR-04 易部署性**：云端 Docker Compose 部署、Caddy HTTPS、Agent Linux 二进制与安装说明、最少外部依赖。
- **NFR-05 测试验收**：至少两个 Agent 联调；测试认证隔离、发现既有容器、Compose 成败、导航生成、重复任务、断线恢复。

## 8. v1 非目标

不做多用户/RBAC、健康检查、Kubernetes、跨 Agent 容器调度、SSH 终端、任意 Shell 执行、完整监控、应用备份恢复、自动更新、完整应用卸载与数据清理、多 Server 集群。OpenWrt 等更多平台放在后续评估。

## 9. MVP 端到端验收

- AC-01 新浏览器首页弱口令验证成功，凭据仍有效时后续免输入。
- AC-02 未持有管理员会话时，所有管理与 Agent 操作 API 拒绝访问。
- AC-03 管理员可增删改导航卡片和分组；独立卡片可不关联 Docker。
- AC-04 管理员可调整排序；首页按编排结果展示。
- AC-05 两个 Agent 可同时连接，显示在线/离线与最近心跳。
- AC-06 Agent 发现已存在的运行中/已停止容器并进入容器池。
- AC-07 可从容器池选容器创建卡片，手动修改 URL。
- AC-08 可选 Agent 和应用模板并填写安装参数与导航草稿。
- AC-09 Compose 返回 0 → 显示部署成功、记录实例、创建一张导航卡片。
- AC-10 Compose 非 0 → 显示失败及日志、不自动创建卡片。
- AC-11 重复任务或重连不产生重复部署/重复卡片。
- AC-12 Agent 离线时保留上次快照并标记过期；重连后恢复同步。
- AC-13 删除导航卡片不会操作或删除容器。
- AC-14 Server 重启后导航、Agent、任务和实例记录仍在。
- AC-15 管理员能启动、停止、重启容器并收到执行结果。

## 10. 未定事项

见 [DECISIONS.md](./DECISIONS.md) 的 Q-01～Q-14。未定事项应在相关任务实施前确认，不应阻止不依赖该决策的工程基础任务。
