# Navloom v1 开发路线图

> 每个里程碑完成的标准是**验收通过**，不是文件数量或代码提交数量。M0 已通过自动化验收；其他任务以各任务文件中的复选框状态为准。

## M0 — 需求与工程基线

**状态：已完成（8/8）**。详见 [M0 实施记录](./M0-IMPLEMENTATION.md)。

**目标**：建立可运行的单仓库开发环境与稳定数据契约。

任务：T-001～T-008。  
交付：Web/Server/Agent 基础项目、共享 API Schema、SQLite 迁移、开发 Compose、CI 检查、环境配置与最小观测能力。

**验收**：新环境可按文档启动；数据库可初始化和迁移；CI 能验证基本构建。

## M1 — 导航可用 + 双层访问控制

**状态：进行中（11/25 项已验收）**。已提交首页/管理员认证、导航 CRUD 与 Vue 管理界面；浏览器交互验收和 M2 依赖的容器关联仍待完成。见 [M1 实施记录](./M1-IMPLEMENTATION.md)。

**目标**：Navloom 可以先作为独立导航产品使用。

任务：T-009～T-033。  
交付：弱口令首页、长期浏览器凭据、管理员登录、导航卡片与分组 CRUD、搜索、排序、响应式首页、后台导航管理。

**验收**：AC-01～AC-04、AC-13。弱口令不能访问管理 API，独立导航卡片正常工作。

## M2 — Agent 接入 + 容器池

**状态：T-036～T-059 按新架构全面重做（仅 T-035 已按旧基线自动化验收；原主动 WSS/心跳代码是待替换历史实现，不能计入新方案验收；容器池尚未实现）**。见 [M2 实施记录](./M2-IMPLEMENTATION.md)。

**目标**：统一查看多台设备上的现有 Docker 容器，并可从容器池创建导航。

任务：T-034～T-059。  
交付：Agent 单次配对、私网双向 TLS、Server 页面驱动按需主动 WSS、全局唯一 Ping/Pong 自动/手动探测、无任何已登录页面零通信且状态冻结（含普通口令导航页的在线计数）、设备列表、容器快照与事件、容器池、基本容器操作、卡片关联。

**验收**：AC-05～AC-07、AC-12、AC-15。至少两台 Agent 联调；外部容器不被误认为 Navloom 部署。

## M3 — 模板驱动安装 + 自动导航

**目标**：打通 Navloom 最核心的安装闭环。

任务：T-060～T-088。  
交付：可信模板、JSON Schema 表单、参数验证、异步持久化任务、Compose 执行、日志、幂等恢复、实例记录、成功后自动创建导航。

**验收**：AC-08～AC-11。成功与失败路径、断线和重复提交均能复现和验证。

## M4 — 安全、可靠性、文档与发布

**目标**：让个人自托管用户能够稳定部署和使用。

任务：T-089～T-102。  
交付：权限/安全测试、数据备份与恢复、Agent/Server 兼容性测试、端到端回归、构建发布、运维文档、最终 MVP 验收。

**验收**：AC-01～AC-15 全部通过，已知限制写入发布说明。

## P1 / P2 需求池

T-103～T-114 是候选增强功能，**不计入 v1 完成条件**，见 [tasks/09-backlog.md](./tasks/09-backlog.md)。

## 关键依赖与阻塞点

- M1 依赖 M0 的数据库、API 与认证基础。
- M2 从 T-036 全面重做：先完成双向 TLS 配对和 Server 主动连接、全局已登录页面在线管理（含普通导航页）与唯一心跳，再开始容器池；旧 CI 不代表新方案通过。
- M3 的安装流程依赖 M2 的 Agent 连接、M1 的导航 API、M0 的任务模型。
- T-052/T-053 在实施前需确定 Q-04 容器池展示方式。
- T-060/T-061 在实施前需确定 Q-08 模板来源。
- T-069/T-085 在实施前需确定 Q-07 是否允许不生成导航卡片。
- 安全与测试不是最后才开始；M4 是最终回归和发布门槛。

## 建议的执行纪律

- 同一时间聚焦一个里程碑；任务按依赖关系领取，而非机械按编号执行。
- 每个任务对应可审查的 PR 或提交；PR 描述引用 T-xxx 与 PRD 需求 ID。
- 任务验收时补充测试证据，更新任务复选框。
- 未确认的产品问题可以阻塞相关任务，但不应阻塞其他独立任务。
